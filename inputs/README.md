# Input files for `diagramc`

`default.json` lists every input key with its default value. Copy it into a run directory and edit it there
(`runs/` is git-ignored):

```
mkdir -p runs/my_run && cp inputs/default.json runs/my_run/input.json
cd runs/my_run && mpirun -n 4 ../../bin/diagramc input.json
```

`default.json` is generated by the program and should not be edited by hand. After any change to the input
structure (`include/io/run_input.hpp`), regenerate it with `bin/diagramc inputs/default.json` (run without an
argument, `diagramc` writes `input.json` in the working directory). Then update this README.

`tests/test_run_input` (`make -C tests run`) checks every `inputs/**/*.json`: each file must load and validate,
and `default.json` must equal what the current code writes. A renamed key, a new key or a changed default makes
the test fail until the file is regenerated.

**Rules for the file:**
- **Every key is optional:** a missing key keeps its default, so an input file may contain only what differs.
- **Unknown keys are an error**, so a typo cannot silently leave a default in place.
- **The whole input is validated before anything runs**, and every violated rule is listed at once (see the
  end of this file).
- **JSON has no comments,** so this README is the documentation.

**Units** are atomic (Hartree, Bohr, ħ = 1). The band energy is E(k) = k² × (eigenvalue of the LK matrix), so a
parabolic band with mass m has A = 1/(2m). Example: AlAs, ω_LO = 47.3 meV = 0.00173824189 Ha.

## Layout

```
{
  "config":       { "model", "diagram", "start", "rng", "measurements", "thermalization", "output" },
  "params":       { production run control (simplemc::simulation_params) },
  "updates":      { "<update>": {"weight": w}, ... },
  "measurements": { "<estimator>": {"is_active": true|false}, ... }
}
```

## `config.model`: the band structure and the phonons

| key | default | meaning |
|---|---|---|
| `A_LK`, `B_LK`, `C_LK` | 1, 1, 0 | Luttinger–Kohn parameters (sign convention: A, B > 0 for the band minimum). They must satisfy A > 0, B > 0, −A/2 − B < C < A + B. A = B with C = 0 is the isotropic Fröhlich model with m = 1/(2A). C = 0 with A ≠ B is uniaxial, with m_par = 1/(2A) and m_perp = 1/(2B). |
| `V_unit_cell`, `V_BvK` | 1, 1 | volumes in the coupling (`Coupling::Parameters`). Leave them at 1 unless you have checked their meaning. |
| `ph_energy` | [1] | LO phonon energy ω of each mode |
| `diel_response` | [1] | ε* of each mode, 1/ε* = 1/ε∞ − 1/ε0; one entry per mode, the same length as `ph_energy` |

Examples:
- **α = 0.5 Fröhlich:** A = B = 1, ω = 1, ε* = 1.
- **AlAs conduction band:** A = 1/(2·0.897), B = 1/(2·0.243), C = 0.
- **AlAs valence band (three degenerate bands):** A = 4.681, B = 1.019, C = 5.498.
- **Both AlAs cases:** ω = 0.00173824189 and ε* = 54.0742079.

## `config.diagram`: the diagram and the length mode

| key | default | meaning |
|---|---|---|
| `p` | [0, 0, 0] | external (total) momentum |
| `tau_fixed` | false | fixed diagram length τ_D (long-τ runs for E₀, Z_N and masses) or variable length (Green functions) |
| `tau_max` | 50 | largest diagram length; in fixed mode it must equal `tau_D_start` |
| `tau_D_start` | 1 | starting length, the fixed length in fixed mode |
| `mu` | −1 | chemical potential: must be 0 in fixed mode and < 0 in variable mode. It controls how the chain spreads over τ_D: choose it close to but below E₀ to reach long τ_D. |
| `tau_min` | 0 | variable mode only: gs_energy, qp_weights and the eff_mass estimators ignore diagrams with τ_D < `tau_min` |
| `max_internal_lines`, `max_external_lines` | 200, 8 | capacity of the diagram. Make it generous: the order must never reach it, since add proposals beyond it are rejected. |

Fixed-length recipe (as in the AlAs runs):
- set `tau_fixed: true`, `tau_max = tau_D_start = τ_D`, `mu: 0`;
- give weight 0 to `chg_tau`, `str_diagram` and `scl_diagram`;
- choose τ_D ≫ 1/ω, e.g. 1e5 for AlAs.

## `config.start`: the starting diagrams
On each rank (one Markov chain per rank), the even ranks start from the bare propagator and the odd ranks from a
random diagram if `random_start` is true. Different starts are what make the R̂ thermalization test meaningful.

| key | default | meaning |
|---|---|---|
| `random_start` | false | random starting diagrams on the odd ranks |
| `n_internal_min`, `n_internal_max` | 0, 0 | number of internal lines, drawn uniformly in this range |
| `n_external_min`, `n_external_max` | 0, 0 | number of external lines. **Keep both at 0** (see the warning below). |
| `w_scale` | 1 | standard deviation of each phonon momentum component. Keep it at most about 2–3 × √(2mω), e.g. ≈ 0.1 for AlAs. |

**Warning:** random external lines with large momenta can lock each other into a configuration the chain never
leaves. R̂ then never passes, and E₀ comes out wrong. See `markdown_notes/external_line_traps.md`. The external
sector is filled by `add_ext_ph` during thermalization anyway. For internal lines, use a range above the expected
order, roughly α ω τ_D lines, so that the chains start on both sides of the target.

## `config.rng`

| key | default | meaning |
|---|---|---|
| `seed` | splitmix64 default | base seed; each rank uses `seed_rng(rng, rank, seed)`. The same seed and input reproduce the same chains. |

## `config.measurements`: estimator settings
Which estimators run is set in the top-level `"measurements"` block (below).

| key | default | meaning |
|---|---|---|
| `n_batches` | 256 | batches of each estimator's accumulator; the jackknife errors come from the batch means |
| `green_n_bins` | 100 | τ bins of green_func and green_trace over (0, τ_max] |
| `boundary_phonons` | 0 | green_*: 0 gives the vacuum sector G(p, τ); n > 0 exactly n external lines; < 0 all of them (the P function) |
| `split_sign` | false | green_trace: also keep the positive and negative parts per bin; their ratio is the average sign per bin |

## `config.thermalization`: the R̂-controlled thermalization
The ranks are the chains. Thermalization ends when R̂ and the bulk and tail ESS pass for `consecutive` checkpoints
in a row, or at `max_steps`. In the second case production runs anyway, and `<prefix>_run.dat` says
"thermalized: NO".

| key | default | meaning |
|---|---|---|
| `enabled` | true | false skips thermalization (not recommended) |
| `monitor_tau_D`, `monitor_energy`, `monitor_orbital` | false, true, false | extra monitored scalars: τ_D (variable mode), the energy, the orbital fractions (only allowed at C = 0). n_int, n_ext, Y²/τ, rms w and rms k are always monitored. |
| `monitor_n_batches` | 256 | batches of the monitor. It must be ≥ 4 × the ESS thresholds, otherwise the test can never pass. |
| `rhat_max` | 1.01 | R̂ threshold |
| `min_bulk_ess_per_split_chain`, `min_tail_ess_per_split_chain` | 50, 50 | ESS thresholds per split chain (each rank counts as 2) |
| `consecutive` | 3 | checkpoints in a row that must pass |
| `root` | 0 | rank that evaluates R̂ |
| `max_steps` | 1e9 | cap per chain |
| `checkpoint_interval` | 1e6 | steps between checkpoints; it must be a multiple of `steps_per_cycle` × `cycles_per_check` |
| `steps_per_cycle` | 10 | steps between two monitor samples |
| `cycles_per_check` | 1000 | cycles between checkpoint and stop checks |

## `config.output`

| key | default | meaning |
|---|---|---|
| `prefix` | "dmc" | path stem of the output files, relative to the working directory; a missing directory is created |

The outputs are:
- `<prefix>_<estimator>.dat` for every active estimator;
- `<prefix>_thermalization.dat`, the R̂ history;
- `<prefix>_run.dat`, with the input, the run statistics, the negative-sign fraction and the update acceptances;
- `<prefix>_input.json`, the full input actually used.

## `params`: the production run, and the wall-time budget of the whole job
This is simplemc's `simulation_params`, with project defaults (`input::defaultParams()`) instead of simplemc's own.

| key | default | meaning |
|---|---|---|
| `max_time` | 84600 (23 h 30 min) | **wall-time budget of the whole job** in seconds: startup, thermalization and production together (see below) |
| `max_steps` | 2⁶⁴ − 1 (unlimited) | production steps per chain; unlimited lets the budget decide |
| `steps_per_cycle` | 10 | steps between two measurements |
| `cycles_per_check` | 1000 | cycles between stop checks (steps and time), i.e. every 1e4 steps |
| `skip_measurements` | false | run without measuring |
| `checkpoint_after_steps`, `checkpoint_after_time` | max | unused (no restart yet) |

How the budget is used:
- **Thermalization** is ended at the first R̂ checkpoint after the budget runs out. The root decides from its own
  clock and the decision is broadcast, so every rank stops at the same checkpoint. A per-rank time limit would
  leave the collective checkpoints unmatched.
- **Production** gets what is left, the same limit on every rank. If less than 60 s is left, production is skipped
  (exit code 3) and only the thermalization log and `<prefix>_run.dat` are written.
- **Stop checks** happen only every `steps_per_cycle × cycles_per_check` steps, so the overshoot is at most one
  block, plus one checkpoint interval for thermalization, plus the time to write the output. On a 24 h queue,
  23 h 30 min leaves margin for that.
- **`<prefix>_run.dat`** records the budget, how long thermalization took, the production limit, and why
  production ended (max_steps reached, budget reached, or skipped).

## `updates`: selection weights
Each update is selected with probability ∝ its weight. add/rm of internal lines and add/rm of external lines are
inverse pairs. The detailed-balance factor w_inverse/w is applied automatically, and within a pair both weights
must be zero or both non-zero.

| update | changes |
|---|---|
| `add_int_ph`, `rm_int_ph` | add or remove an internal phonon line |
| `add_ext_ph`, `rm_ext_ph` | add or remove an external line (a phonon present at the boundary) |
| `swp_ph` | swap the ends of two lines |
| `mv_tau` | move a vertex in time |
| `chg_ph_momentum` | new momentum for a line |
| `chg_ph_energy` | new phonon mode for a line (useless with one mode: give it weight 0) |
| `chg_tau`, `str_diagram`, `scl_diagram` | change τ_D: weight 0 in fixed mode, at least one > 0 in variable mode |

All defaults are 1. A larger weight on one side of a pair pays only where its proposals are mostly accepted; see
`markdown_notes/lk_bands_implementation.md` §16.5.

## `measurements`: which estimators run

| estimator | default | requires |
|---|---|---|
| `gs_energy` | on | — |
| `qp_weights` | on | — (meaningful with external lines) |
| `eff_mass` | off | A = B and C = 0; fixed τ if p ≠ 0 |
| `eff_mass_uniaxial` | off | C = 0; fixed τ if p ≠ 0 |
| `green_func` | off | variable length |
| `green_trace` | off | variable length |

## Validation rules (checked before the run)
- **LK parameters:** within the bounds listed under `config.model`.
- **Phonon modes:** at least one; ω > 0 and ε* > 0; the two arrays have the same length.
- **Fixed length:** `tau_D_start == tau_max`, `mu == 0`, and weight 0 for the three length-changing updates.
- **Variable length:**
  - `mu < 0`;
  - 0 < `tau_D_start` ≤ `tau_max` and 0 ≤ `tau_min` < `tau_max`;
  - at least one length-changing update with weight > 0.
- **Update weights:** finite and ≥ 0; inverse pairs both zero or both non-zero; at least one > 0.
- **Starts:** the random-start ranges fit the line capacities.
- **Thermalization:**
  - `monitor_n_batches` ≥ 4 × the ESS thresholds;
  - `checkpoint_interval` a multiple of `steps_per_cycle × cycles_per_check`;
  - `monitor_orbital` only at C = 0.
- **Estimators:** the requirements listed under `measurements`.

## Running on the hybrid-core laptop
Under OpenMPI 4.1, `mpirun --cpu-set` is ignored. To avoid the slow low-power cores (12, 13), restrict the run with
`taskset`:

```
taskset -c 0,2,4-11 mpirun -n 10 --bind-to none ../../bin/diagramc input.json > run.log 2>&1
```

The R̂ checkpoints are collective, so the slowest chain sets the pace.
